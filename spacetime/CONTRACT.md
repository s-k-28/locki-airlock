# AIRLOCK SpacetimeDB contract v1

Frozen integration names, 2026-11-07. Module `spacetime/src/index.ts`; all backing tables PRIVATE. Subscribe ONLY to the caller-scoped `my_*` views below. Generated TS reducer/field accessors are camelCase; SQL names snake_case. Every timestamp ending `Ms` is UTC epoch milliseconds, `u64` / SDK `bigint`. `u32` and `f64` are SDK number. All `*Json` are JSON strings. Missing IDs are empty strings. Identity fields use SDK `Identity`, supplied identities to reducers are 64-hex strings.

## Reducers (named argument objects)

- `register_workstation({workstationId:string,name:string})`: caller becomes owner of NEW id; cannot seize existing station.
- `enroll_device({workstationId:string,deviceId:string,identityHex:string,role:string,label:string})`: owner only, role `mac|jetson|service`.
- `grant_reviewer({workstationId:string,identityHex:string,canApprove:bool})`: owner only.
- `revoke_member({workstationId:string,identityHex:string})`: owner only.
- `set_policy({workstationId:string,autoLockEnabled:bool,lockCooldownMs:u64})`: owner, new policy version/hash; takes effect next arm.
- `record_baseline({workstationId:string,deviceId:string,observedAtMs:u64,baselineJson:string,activeAppId:string})`: enrolled matching Mac only. Successful actual redacted USB inventory, canonical string-array JSON; active bundle ID or explicit `"unknown"`. Observation at most 30s old / 5s future and nonregressing. Upserts `latest:<deviceId>`, captures current server health, and refreshes USB health online. It does not assert that the continuous application-launch observer is running. Re-enrollment clears the latest capture and old device health; frozen session captures are immutable. Adapters must report actual captures, never fabricate an empty inventory after an OS-read failure.
- `arm_session({workstationId:string,sessionId:string,baselineJson:string,approvedAppsJson:string,durationMs:u64,simulated:bool})`: owner; duration 1 min–24h. Live mode requires the freshest still-enrolled Mac capture (observed ≤30s ago) with same-device online USB health ≤15s old. `baselineJson:""` uses that capture automatically; a nonempty JSON array must exactly match its normalized inventory. Copies the capture into `session:<sessionId>` and freezes activeAppId plus server-derived camera/health state at arm time. Camera offline/unavailable does NOT block healthy USB arming. USB baseline, app allowlist, consent and policy hash stay frozen in the session. Simulated mode still accepts explicit manual fixture baseline JSON, accepts simulated evidence only and NEVER emits real lock.
- `disarm_session({workstationId:string})`: owner; cancels pending locks and starts owner-return grace.
- `ingest_device_event({workstationId:string,sessionId:string,deviceId:string,eventId:string,kind:string,observedAtMs:u64,seq:u64,confidence:f64,metadataJson:string,simulated:bool,schemaVersion:u32})`: enrolled matching sender. Owner may publish simulated fixtures using `deviceId:"fixture"` ONLY in simulated sessions. Mac kinds `usb_added|usb_removed|app_launched`; Jetson `person_in_zone|person_cleared|camera_offline|camera_online`; `heartbeat` all. service cannot fabricate sensor events. Metadata usb `{deviceKey:string,label?:string}`; app `{appId:string,label?:string}`; camera `{detail?:string}`. EventId globally unique and changed duplicate payload rejected; seq monotonic per enrolled device; bounded to 64 accepted events/device/second and 100000 non-heartbeat events/session; clock freshness 120s, future skew 5s, observation must be within armed interval. Lock trigger freshness separately limited to 15s. USB unapproved opens medium incident independent of camera; repeated same-key observations join the unresolved session incident and do not create a second lock request; physical <=10s upgrades high in either arrival order. Approved USB info only; person alone observation only.
- `report_health({workstationId:string,deviceId:string,component:string,status:string,detail:string})`: enrolled sender, component constrained to device role; status `online|degraded|offline|unavailable`. Generic heartbeat components are mac=watcher, jetson=jetson, service=gateway; USB/app observations refresh usb/apps respectively. Gateway liveness never implies model health.
- `acknowledge_incident({incidentId:string,note:string})`: owner/reviewer.
- `request_incident_info({incidentId:string,note:string})`: owner/reviewer, sets reviewing.
- `resolve_incident({incidentId:string,note:string})`: OWNER only, note required.
- `request_lock({incidentId:string})`: OWNER only; frozen session auto-lock consent required; same narrow deterministic trigger/cooldown/deadline as auto-lock.
- `report_lock_result({actionId:string,status:string,detail:string})`: target enrolled Mac only. status `executed|confirmed|failed`; executed does not mean confirmed. New live-session lock requests target the identity-bound Mac capture frozen at arm time. No real system lock is executed by DB.
- `propose_protected_action({workstationId:string,actionId:string,missionId:string,incidentId:string,toolName:string,argsJson:string,scope:string,ttlMs:u64})`: enrolled service or owner; normalized args canonicalized, server SHA256 binds all exact immutable action content, max ttl 5min. Pending action is NOT permission. Owner-created proposals are review-only and cannot be consumed by a service; executable proposals originate from their intended gateway service.
- `decide_action({actionId:string,approve:bool,ttlMs:u64,note:string})`: owner or reviewer with canApprove; cannot approve own proposal. Revocation or loss of canApprove invalidates outstanding grants; consumption rechecks current approver permission. Produces one-time approval using action id and server digest.
- `consume_approval({actionId:string,approvalId:string,actionDigest:string,executionId:string})`: the SAME enrolled service that proposed the action only; atomic exact digest/scope/expiry, one use. Gateway MUST await committed success before callback. Denial throws; no callback should run.
- `report_action_result({actionId:string,executionId:string,status:string,detail:string})`: consuming service only, status `succeeded|failed|uncertain`.
- `record_agent_step({workstationId:string,runId:string,incidentId:string,stepId:string,step:u32,toolName:string,status:string,evidenceId:string,durationMs:u64,inputType:string,argsJson:string,resultSummary:string,traceId:string,model:string})`: service only, real adapter reported steps. status `running|succeeded|failed|complete`; metadata redacted, no chain of thought. First service owns the run; model and trace stay fixed, step numbers strictly increase, terminal runs reject further steps.
- `refresh_workstation({workstationId:string})`: any enrolled member; marks elapsed session/actions expired and stale health offline. Optional client-triggered refresh; ingest also refreshes. A PRIVATE durable interval schedule runs every 5s per workstation independent of browsers and marks a silent publisher offline after 15s. The unique workstation index prevents duplicate schedules. Existing workstations are lazily scheduled on first refresh/ingest after upgrade.

## Authorized views and row fields

Every row has `workstationId:string` unless workstation itself (`id`). Fields listed below are exact and required. Views use membership index by ctx.sender; no unscoped public tables. Owner/reviewer/service can read case data. An enabled enrolled Mac can also read its workstation's `my_incidents` and `my_device_events`, including correlated Jetson observations, for incident-to-voice delivery. Mac/Jetson see station/session/health and own enrollment; Jetson cannot read incidents/events. Only the target Mac identity sees its lock requests. Mac observation access grants no reviewer, protected-action, approval, agent-trace or audit permissions. Revocation or loss of the last matching enabled device removes access. Approvals view is owner/authorized reviewer/service only and never contains secret credentials.

- `my_workstations`: `{id:string,name:string,owner:Identity,createdAtMs:u64,activeSessionId:string,autoLockEnabled:bool,policyVersion:u32,ownerPolicyHash:string,lockCooldownMs:u64,lastLockRequestedAtMs:u64,returnGraceUntilMs:u64}`
- `my_memberships`: `{id:string,workstationId:string,identity:Identity,role:string,canApprove:bool,enabled:bool,createdAtMs:u64}`; own membership only.
- `my_devices`: `{id:string,workstationId:string,identity:Identity,role:string,label:string,enabled:bool,lastSeq:u64,lastEventAtMs:u64}`
- `my_sessions`: `{id:string,workstationId:string,state:string,armedBy:Identity,armedAtMs:u64,expiresAtMs:u64,disarmedAtMs:u64,baselineJson:string,approvedAppsJson:string,autoLockEnabled:bool,ownerPolicyHash:string,simulated:bool}`
- `my_baseline_snapshots`: `{id:string,workstationId:string,deviceId:string,publisher:Identity,observedAtMs:u64,receivedAtMs:u64,baselineJson:string,activeAppId:string,sessionId:string,cameraStatus:string,healthJson:string}`; latest rows have empty sessionId, frozen rows have their session ID. Owner/reviewer/service see station captures; Mac sees only its own; Jetson/outsider see none. `healthJson` is a server-derived array of `{deviceId,component,status,lastSeenMs:string}` with no private detail payload; cameraStatus is `online|degraded|offline|unavailable`. No camera reports means unavailable. These are authenticated adapter observations, not hardware attestation.
- `my_device_events`: `{id:string,workstationId:string,sessionId:string,deviceId:string,source:string,kind:string,observedAtMs:u64,receivedAtMs:u64,seq:u64,confidence:f64,metadataJson:string,simulated:bool,schemaVersion:u32,classification:string}`
- `my_incidents`: `{id:string,workstationId:string,sessionId:string,severity:string,state:string,ruleId:string,summary:string,eventIdsJson:string,digitalEventId:string,physicalEventId:string,createdAtMs:u64,updatedAtMs:u64,acknowledgedBy:string,resolvedBy:string,resolutionNote:string,actionRequired:bool,simulated:bool}`; severity `medium|high`, state `open|acknowledged|reviewing|resolved`.
- `my_device_health`: `{id:string,workstationId:string,deviceId:string,component:string,status:string,lastSeenMs:u64,detail:string}`
- `my_lock_requests`: `{id:string,workstationId:string,sessionId:string,incidentId:string,targetDeviceId:string,status:string,issuedAtMs:u64,expiresAtMs:u64,reason:string,ownerPolicyHash:string,simulated:bool,resultDetail:string,updatedAtMs:u64}`
- `my_protected_actions`: `{id:string,workstationId:string,missionId:string,incidentId:string,proposedBy:Identity,toolName:string,argsJson:string,scope:string,actionDigest:string,status:string,createdAtMs:u64,expiresAtMs:u64,approvalId:string,executionId:string,consumedBy:string,resultDetail:string}`
- `my_approvals`: `{id:string,workstationId:string,actionId:string,actionDigest:string,approvedBy:Identity,status:string,createdAtMs:u64,expiresAtMs:u64,consumedAtMs:u64,note:string}`
- `my_agent_runs`: `{id:string,workstationId:string,incidentId:string,model:string,status:string,startedAtMs:u64,updatedAtMs:u64,traceId:string}`
- `my_agent_steps`: `{id:string,workstationId:string,runId:string,incidentId:string,step:u32,toolName:string,status:string,evidenceId:string,durationMs:u64,inputType:string,argsJson:string,resultSummary:string,traceId:string,createdAtMs:u64}`
- `my_acknowledgements`: `{id:u64,workstationId:string,incidentId:string,actor:Identity,kind:string,note:string,createdAtMs:u64}`

## Client calls

Subscribe `SELECT * FROM my_workstations` etc. Generated accessor e.g. `connection.db.myIncidents.iter()`; reducers `connection.reducers.registerWorkstation({workstationId:"sid-desk",name:"Sid's desk"})`. All calls are server-authorized; unauthorized clients see zero view rows. Keep auth token private in each browser context and reuse it on reconnect. Do not use subscribeToAllTables (backing tables private).

## Conservative prototype bounds

The 15s heartbeat timeout, 15s lock-trigger freshness, 5s maintenance interval, 64 events/device/second and 100000 non-heartbeat events/session are explicit conservative engineering limits, not values learned or calibrated from hardware trials. Live baselines are authenticated Mac captures, frozen at arm time; simulated baselines remain explicit owner fixtures. Device IDs/USB keys should be salted local digests, never raw hardware serials. Event metadata accepts only deviceKey/appId/label/detail/captureMode/bootId string fields <=256 characters; adapters remain responsible for redacting the contents of these fields. Raw video, screenshots, speech and device files are never accepted by this contract.

## Short metadata retention

The existing private 5s scheduled maintenance performs a maximum of **200 row deletions per tick per workstation**, after expiry processing. Default retention is **24 hours**, with no client-supplied deletion cutoff. A session becomes eligible only after it ended at least 24h ago, all its cases have been resolved for at least 24h, all related actions are terminal, expired, and have no action-audit update within 24h, and all investigations are terminal and unchanged for at least 24h. The entire session is preserved while any case is unresolved or an investigation/action is pending or consumed without a terminal result. This deliberately retains relevant evidence beyond 24h when review is incomplete.

Cleanup removes approvals with their actions atomically, then steps/runs, lock requests, acknowledgements, incidents, events, frozen captures and finally sessions. Larger sessions drain over multiple ticks without dangling evidence references. Old standalone terminal actions, stale latest captures and audit rows with no retained entity are also removed. Run-origin audit records remain while their run exists because they bind the reporting service. Configuration, memberships, enrollment and latest component health remain operational state. Audit is append-only to application callers, but subject to this explicit retention process. Workstation-indexed candidate reads are not a global fixed scan budget; the 200-row limit bounds deletions. This governs the live database, not backup copies or external evidence files, whose retention remains a deployment responsibility.


## Final execution and enrollment hardening

`claim_lock({actionId:string,executionId:string})` (`claimLock` in generated SDK) atomically spends one execution authorization in PRIVATE `lock_claims`, revalidates current/frozen owner policy, live non-synthetic session, frozen baseline Mac publisher, target identity, unresolved actionable incident, request expiry, return grace and supersession, then changes the request to `executing`. Exactly one claim may commit for an action. Reported execution requires that claim; `requested`/`executing` requests expire or cancel normally, and spent authorization is never reissued after a crash. The adapter must await successful commit before its fixed helper. No public view fields changed.

`panic_session({workstationId:string,reason:string})` is owner-only and requires an armed session. It records explicit manual intent as `owner_panic`, severity high, with no invented sensor evidence and keeps the session armed. It only requests a lock under the existing consent/baseline/cooldown gates; local consent and a one-time claim are still required. Repeated owner panic updates the same session incident without issuing a second lock for it.

Replacing a device identity revokes the old membership and unspent grants when no enabled device remains for it. Multiple enabled devices of the same role may deliberately share an identity. Different roles cannot share that workstation identity. Service mutations require a matching enabled service device; stale orphan memberships cannot expose views.

Heartbeat observations do not count toward security-event capacity. Unreferenced heartbeats retain a rolling 128 rows per device/session for bounded retry/dedup and rate checks; incident/agent evidence is preserved. Heartbeat noise is not appended to the application audit journal. Security-event capacity is 100000 per session, covering a 24-hour 5-second presence feed. The last accepted event at capacity atomically commits sticky degraded coverage; heartbeats cannot make protection green again until the session ends. Explicit capacity errors require owner review/rearm.
